# So-ARM シリーズ キャリブレーションツール

**So-ARM 10X シリーズのロボットアーム向け FTServo サーボ用、工場キャリブレーション＆LeRobot キャリブレーション ツールキット**

> ⚠️ **互換性に関する注意：本システムは現在、Feetech（STS3215 シリーズ）サーボのみに対応しています。** レジスタテーブル、xdat パラメータ形式、ボーレートテーブルはすべて Feetech STS3215 シリーズ向けに設計されています。他社製・他モデルのサーボについては互換性を保証しません。

> 📜 **由来とクレジット：本ツールは [Seeed Studio の Seeed_RoboController](https://github.com/Seeed-Studio) を基に構築・拡張したものです**（MIT ライセンスで公開）。本プロジェクトは元のコア機能を維持しつつ、GUI を刷新し、FT デバッガー、xdat パラメータのバックアップ／復元、クロスプラットフォーム対応などの拡張を追加しています。詳細は [LICENSE](../../LICENSE) を参照してください。

| ---- | ---- |

| クロスプラットフォーム対応 | Windows / Ubuntu / macOS で動作します |

| モーター無効化 | ワンクリックですべてのサーボのトルクを無効にし、手動調整を可能にします |

| 単一ファイル配布 | PyInstaller で 1 つの exe にまとめます。対象マシンに Python は不要で、すべてのコマンドラインツールが同じ exe に内蔵されています |
| キャリブレーションファイルから中心へ移動 | キャリブレーションファイルに基づいてアームを中心へ移動します |

## 🖥️ インターフェース概要

メインプログラムは 3 つのタブで構成されています：

```
┌─────────────────────────────────────────────────────────────────┐
│  SoARM 校正ツール [Leader▾] [Follower▾] [🔄] [🎮 リモート][EN]  │  ← トップバー
├─────────────────────────────────────────────────────────────────┤
│  ┌─────────────────────────────┬──────────────────────────────┐ │
│  │ Leader - サーボ校正         │ Follower - サーボ校正        │ │
│  │ [🔴 未接続] 現在:…          │ [🔴 未接続] 現在:…           │ │
│  │ サーボ1〜6 状態テーブル     │ サーボ1〜6 状態テーブル      │ │
│  │ [中心校正][中心テスト]…     │ [中心校正][中心テスト]…      │ │
│  └─────────────────────────────┴──────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

- **トップバー**：アプリケーションのタイトル、リーダー／フォロワーアームのポートドロップダウン、更新、リモート操作、言語切り替え。
- **🦾 タブ1 — サーボキャリブレーション**：左右のパネルでのクイック操作（中心キャリブレーション、中心テスト、モーター無効化）とリアルタイムのステータス表示。**中心キャリブレーション**は LeRobot キャリブレーションウィザード（第 2 節を参照）を開き、アーム全体のキャリブレーションを一括で行います。
- **🎚️ タブ2 — 単一サーボ制御**：サーボごとに 1 行 —— ID / Pos 値 / スライダー / L（目標値）。Pos とスライダーは**双方向にバインド**されています：スライダーをドラッグすると Pos が更新され、Pos に数値を入力するとスライダーが移動し、直ちに位置コマンドが送信されます。
- **🔬 タブ3 — FT デバッガー**：シリアル接続、スキャン、パラメータの読み書き、位置制御、ボーレート／工場出荷時リセット、xdat パラメータのバックアップと復元。

## 🚀 クイックスタート

> システムごとの詳細な手順は [📚 OS別ガイド](#-os別ガイド) を参照してください。各システムの要点は以下のとおりです。

### Windows

1. [Python 3.10+](https://www.python.org/downloads/) をインストールします（**Add to PATH** にチェック）。
2. 仮想環境を作成し、依存関係をインストールします：

```bash
cd SO-ARM101-ServoController
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

3. 環境を確認して起動します（2 つのエントリーポイントは同等です）：

```bash
python setup.py
python main.py
# または
python -m src.gui.factory_calibration_tool
```

> **Windows でのインストール不要の方法**：`dist\SO-ARM101-ServoController.exe` をダブルクリックするだけです。対象マシンに Python は不要です。再ビルドは `pyinstaller -y SO-ARM101-ServoController.spec` で行います。同じ exe にはすべてのコマンドラインツールも内蔵されています（第 10 節を参照）。

4. デバイスマネージャーで COM ポート（例：`COM3`）を確認し、トップバーで選択します。ポートを手動で指定するには：

```bash
python -m src.gui.factory_calibration_tool --port1 COM3 --port2 COM4
```

### Linux (Ubuntu / Debian)

1. CJK フォントと依存関係をインストールします：

```bash
sudo apt install python3-venv fonts-noto-cjk fonts-noto-color-emoji
```

2. **⚠️ シリアルポートの権限（dialout グループ）を追加します**［必須］：

```bash
sudo usermod -a -G dialout $USER
# ログアウトして再ログインすると有効になります
```

3. 仮想環境を作成し、依存関係をインストールして起動します：

```bash
cd SO-ARM101-ServoController
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python setup.py
python -m src.gui.factory_calibration_tool
```

4. シリアルデバイスは `/dev/ttyUSB0` / `/dev/ttyACM0` です。手動で指定するには：

```bash
python -m src.gui.factory_calibration_tool --port1 /dev/ttyUSB0 --port2 /dev/ttyUSB1
```

### macOS

1. Homebrew で Python をインストールします：

```bash
brew install python
```

2. 仮想環境を作成し、依存関係をインストールして起動します：

```bash
cd SO-ARM101-ServoController
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python setup.py
python -m src.gui.factory_calibration_tool
```

3. **⚠️ シリアルポートの命名**：macOS では `/dev/tty.*` ではなく `/dev/cu.usbserial-*`（**推奨、ノンブロッキング**）を使用します。一覧を表示するには：

```bash
ls /dev/cu.*
```

手動で指定するには：

```bash
python -m src.gui.factory_calibration_tool --port1 /dev/cu.usbserial-0001 --port2 /dev/cu.usbmodem141101
```

### 汎用コマンドラインツール（GUI 不要）

```bash
# サーボをスキャン
```

## 📖 使用手順

### 1. サーボの接続と検出

1. USB-シリアルアダプターを介してアームの制御基板を接続し、サーボに電源を供給します。
2. GUI を開き、トップバーのシリアルドロップダウンから該当するポートを選択します（または `🔄` をクリックして更新）。
3. パネル上部に `🟢 Connected` が表示され、ID が 1〜20 の範囲（通常は 1〜6）にあるオンラインサーボを自動的にスキャンします。

> ポートが使用中と表示される場合は、他のプログラム（シリアルモニターや、終了していない過去の実行など）がポートを占有していないことを確認してください。

### 2. 中心キャリブレーション（リーダーアーム / フォロワーアーム）

> キャリブレーションの前に、各関節が目的の「ゼロ／中心」位置になるよう、アームを物理的に配置してください。

トップバーの **リーダーアーム中心キャリブレーション** / **フォロワーアーム中心キャリブレーション** ボタンは LeRobot キャリブレーションウィザードを開きます。ウィンドウは 2 列に分かれます：左側は 6 つのサーボのリアルタイムモニター（ID / Pos / スライダー）、右側はキャリブレーションテーブルと操作ボタンです。

1. 接続すると、プログラムはトルクを無効化してサーボをリセットします：ホーミングオフセットをゼロにし、角度リミットを `[0, 4095]` に開放します（LeRobot の `reset_calibration` に相当）。
2. **中位の記録を開始** をクリックします —— ボタンがオレンジ色になり、テーブルの「中位値」列が**左側の Pos をリアルタイムに追従**し始めます。アームを標準的な中位に配置し、読み値が安定したら **中位の記録を完了** をクリックして数値を確定し、サーボへ書き戻します（ファイルには増分 `中位値 − 2047` を保存します）。
3. **範囲を記録** をクリックします —— ボタンが緑色になります。**各関節を一端から他端まで動かします**（`wrist_roll` は連続回転関節で、範囲は `[0,4095]` に固定されています；**グリッパーも動かしてください**）。最小／最大値の列はリアルタイムに更新されます。完了したら **範囲の記録を停止** をクリックします。
4. 6 つの関節すべてが完了すると、プログラムは**キャリブレーションファイルを自動保存し、同名の既存ファイルを上書き**し、オフセットとリミットをサーボ EEPROM に書き戻します —— これにより LeRobot が再度キャリブレーションを要求することはなくなります。

保存場所（固定 ID）：

| アーム | キャリブレーションファイル ID | パス |
| --- | --- | --- |
| リーダー | `my_leader_arm` | `~/.cache/huggingface/lerobot/calibration/teleoperators/so_leader/my_leader_arm.json` |
| フォロワー | `my_follower_arm` | `~/.cache/huggingface/lerobot/calibration/robots/so_follower/my_follower_arm.json` |

> ウィザードを途中で閉じると、現在の進捗を保存するか確認されます。「はい」を選んだ場合も同じファイルを上書きします。
> サーボ単体の **🎯 中位** ボタンは、そのサーボの現在位置を 2048 として焼き込む（EEPROM に永続化）ものであり、上記のアーム全体のキャリブレーションとは別の操作です。

> ⚠️ **両方のアームを同じ行程で動かしてください**：遥操作は各アームをそれぞれ記録した範囲で正規化します。ある関節を一方のアームでは途中までしか動かさず（例：shoulder_lift の記録が 107°）、もう一方では 208° まで記録した場合、フォロワーの動作量がリーダーのほぼ 2 倍になり、静止姿勢も一致しません。キャリブレーション後に 2 つのアームの範囲幅を比較し、大きく異なる関節は記録し直してください。

### 3. 中心テスト

1. **リーダーアーム中心テスト** / **フォロワーアーム中心テスト** をクリックします。
2. プログラムはトルクを有効にし、すべてのサーボを 2048 へ移動します。
3. サーボが現在位置からほとんど動かなければキャリブレーションは正しく、大きく動く場合はキャリブレーション値が信頼できないため、やり直す必要があります。

### 4. モーターの無効化（手動調整）

- **リーダーアーム モーター無効化** / **フォロワーアーム モーター無効化** をクリックすると、そのポート上のすべてのサーボのトルクが無効になり、手で自由に回転できます。
- 個々のサーボは **単一サーボ制御** タブで、スライダー下のトルクスイッチを使って切り替えられます。

### 5. 単一サーボ制御（スライダー / Pos）

**🎚️ 単一サーボ制御** タブでは、オンラインのサーボごとに 1 行が表示されます：

- **Pos 数値ボックス**：目標位置（0–4095）を表示／入力します。**編集可能**で、スライダーと双方向にバインドされています。
- **スライダー**：ドラッグ中は Pos がリアルタイムに追従し、位置コマンドは**離したとき**に送信されます（ドラッグ中に連続して送信されません）。
- **Pos への入力**：Enter、フォーカスアウト、またはスピンボタンで直ちにコマンドを送信します。キー入力ごとに 1 桁ずつ送信されることはありません。
- **L**：最後に送信した目標値。
- サーボの動作中、スライダーと Pos は**実際の現在位置**に追従します。ドラッグ中や入力中に値が奪われることはありません。
- 各行には **⚡ トルク**、**🎯 中位**、**🧹 リミット解除** もあり、それぞれそのサーボ単体のトルク切替、現在位置を 2048 として書き込み、角度リミットの解除を行います。

### 6. サーボ ID の変更

1. **🔬 FT デバッガー** タブを開き、シリアルポートに接続してサーボをスキャンします。
2. 対象のサーボを選択し、パラメータテーブルの「Servo ID」値（アドレス 0x05）を変更して「書き込み」をクリックします。
3. プログラムは続いて次を実行します：ロック解除 → アドレス 5 に書き込み → 新しい ID を検証 → 再ロック。

> ⚠️ ID を変更する前に、ID の競合を避けるため、バス上にこのサーボだけが接続されていることを必ず確認してください。

### 7. ボーレートの変更／工場出荷時設定へのリセット

- **ボーレートの変更**：FT デバッガータブの「ボーレート／工場出荷時リセット」エリアで、新しいボーレート（38400 – 1000000 bps）を選択して適用します。書き込み後、シリアルのボーレートが自動的に切り替わり、ping で検証されます。失敗した場合は自動的にロールバックします。
- **工場出荷時設定へのリセット**：サーボは工場出荷時の既定値（ID=1、ボーレート=1000000）に戻ります。その後、再スキャンが必要です。

### 8. xdat パラメータのバックアップと復元

FT デバッガータブの「xdat パラメータ（EEPROM のみ保存）」エリアで：

1. **💾 現在のサーボを保存**：選択したサーボの EEPROM パラメータを xdat ファイルとして保存します（バックアップ）。
2. サーボのパラメータを任意に変更した後、元に戻したい場合：
3. **📂 xdat を開く**：バックアップファイルを読み込みます。
4. **📤 サーボへパラメータを復元**：バックアップを現在のサーボの EEPROM に書き戻します。

### 9. 2 ポート同期リモート操作

> ⚠️ **方向に関する注意：リーダーアームがフォロワーアームを制御します。** リーダーアーム（マスター）はサーボの角度を読み取るだけで、フォロワーアーム（スレーブ）が同期して駆動されます。

1. トップバーで **🎮 リモート** をクリックします（リーダーアームが角度を読み取り → フォロワーアームが同じ ID のサーボを同期して駆動）。
2. 2 つのポートは一致するサーボ ID を使用する必要があり、両方に存在するサーボのみが同期されます。
3. 同じボタンをもう一度クリックすると停止し、その後、両方のパネルのスキャンスレッドが自動的に再開します。

### 10. LeRobot キャリブレーション（コマンドライン）

```bash
# フォロワーアームをキャリブレーション（~/.cache/huggingface/lerobot/calibration/robots/so_follower/ に保存）
python -m src.tools.lerobot_calibrate --arm-type follower

# リーダーアームをキャリブレーション
python -m src.tools.lerobot_calibrate --arm-type leader
```

手順：サーボを無効化 → キャリブレーションパラメータをリセット（オフセットをゼロに、リミットを開放）→ 各関節を中位に配置して `homing_offset` を記録 → 全可動範囲をゆっくり回転させて `range_min/max` を記録（`wrist_roll` は連続回転関節で、範囲は `[0,4095]` に固定）→ パラメータをサーボに書き戻す → JSON を保存。

`homing_offset` は LeRobot 口径の**増分**（中位の生位置 − 2047）であり、生位置そのものではありません。

> GUI の **リーダーアーム中心キャリブレーション / フォロワーアーム中心キャリブレーション** ボタンは同じ手順を実行し、完了時に固定 ID へ自動保存します（上記の第 2 節を参照）。

キャリブレーションファイルから中心へ移動：

```bash
python -m src.tools.run_calibration_middle <calibration_file.json> --mode zero
```

## ⚠️ 注意事項

1. **安全第一**：中心キャリブレーションは EEPROM に永続化されます。キャリブレーションの前に、電源が安定していること、アームが人や物に衝突しないことを確認してください。
2. **電源供給**：SoARM 101 標準版は DC 5V 5A、Pro 版は DC 12V 5A での給電が最適です。電力が不足すると脱調や通信エラーが発生します。
3. **シリアルポートの排他利用**：Windows ではシリアルポートが排他制御されるため、同じポートを GUI のスキャンスレッドとキャリブレーションのサブプロセスが同時に使用することはできません。本ツールは操作前にスキャンスレッドを停止し、古いプロセスを終了させます。手動で繰り返しクリックしないでください。
4. **Linux のシリアル権限**：`/dev/ttyUSB*` / `/dev/ttyACM*` にアクセスするには、ユーザーを `dialout` グループに追加する必要があります（[Linux ガイド](Linux.md) を参照）。
5. **macOS のシリアル命名**：`/dev/tty.*`（ブロッキング、ハングする可能性あり）ではなく `/dev/cu.*`（ノンブロッキング）を使用してください。[macOS ガイド](macOS.md) を参照。
6. **ホットプラグ**：USB ケーブルを抜くと、プログラムは自動的に再接続を試みます。再び接続したら `🔄` をクリックしてポート一覧を更新してください。
7. **過温度／過電圧保護**：プログラムは電圧と温度を監視します（60°C を超えると警告）。サーボが高温のままの場合は停止し、冷ましてください。
8. **中心キャリブレーションは不可逆です**：書き込みは元のオフセットを上書きし、元に戻すことはできません。キャリブレーションの前に元の位置を記録してください。
9. **ID 変更のリスク**：書き込みまたは検証に失敗した場合、プログラムはエラーを報告してスキャンを再開しますが、極端な場合にはサーボが「見失われる」ことがあります。その場合は「工場出荷時設定へのリセット」を試してください（リセット後、ID は 1 に戻ります）。
10. **文字エンコーディングの問題**：Windows のコンソールで絵文字が文字化けする場合は、コマンドラインツールを実行する前に `PYTHONIOENCODING=utf-8` を設定してください。Linux/macOS はネイティブの UTF-8 を使用しており、通常は影響を受けません。
11. **両方のアームの範囲を一致させる**：遥操作は各アームが記録した範囲で正規化されます。ある関節を一方のアームでは途中までしか動かさず、もう一方では最後まで動かした場合、フォロワーの動作量がリーダーより明らかに大きくなり、静止姿勢も一致しません。2 つのアームの範囲幅を比較し、大きく異なる関節は記録し直してください。
12. **グリッパーも動かす**：グリッパーは連続回転関節ではありません。動かさないと範囲が既定の `[0,4095]` になり、開閉の動作量が不正確になります。

## 🛠️ トラブルシューティング

| 症状 | 考えられる原因 | 解決策 |
| ---- | -------- | -------- |
| シリアルポートを開けない／ポートが使用中 | 別のプログラムが使用している | シリアルモニターなどのプログラムを閉じるか、別のポートに切り替えてツールを再起動してください |
| サーボが見つからない | 電力不足／配線ミス／ボーレートの不一致 | 電源と配線を確認し、サーボが 1M ボーであることを確認してください |
| 中心キャリブレーション後にサーボが暴走する | キャリブレーション前に姿勢を設定していない | 「無効化 → 手で配置 → 中心キャリブレーション」を繰り返してください |
| 温度が上昇しすぎる | 負荷が大きすぎる、または関節がストールしている | 機構の引っかかりを確認し、速度／加速度を下げてください |
| ID 変更後にサーボが見つからない | ID の競合または書き込み失敗 | 工場出荷時設定にリセットして再スキャンしてください |
| リモート操作が同期しない | 2 つのポートの ID が異なる | マスターポートとスレーブポートで同じ ID のサーボがオンラインであることを確認してください |
| 遥操作時に 2 つのアームの姿勢／動作量が一致しない | 2 つのアームで一部の関節の記録範囲幅が大きく異なる | その関節を全行程で記録し直し、2 つのアームの範囲を近づけてください |
| グリッパーの動作量がおかしい | グリッパーの範囲を記録していない（既定の `[0,4095]`） | 再キャリブレーション時にグリッパーを一端から他端まで動かしてください |
| キャリブレーションウィザードで Pos が更新されない | ポートが使用中／サーボが応答しない | ポートを占有しているプログラムを閉じてください。6 つのサーボすべてがオンラインであることを確認してください |
